# Android macrobenchmark

The `:benchmark` instrumentation module contains cold-start and library-scroll timing scenarios using `StartupTimingMetric`/`FrameTimingMetric`. Build the isolated, signed test APK with `./gradlew :benchmark:assembleBenchmark`. Install and run only on an explicitly selected device (example serial shown):

```sh
adb -s emulator-5580 install -r app/build/outputs/apk/benchmark/app-benchmark.apk
adb -s emulator-5580 install -r benchmark/build/outputs/apk/benchmark/benchmark-benchmark.apk
adb -s emulator-5580 shell am instrument -w -r -e androidx.benchmark.suppressErrors EMULATOR -e class com.autoanime.android.benchmark.StartupBenchmark com.autoanime.android.benchmark.test/androidx.test.runner.AndroidJUnitRunner
```

The benchmark module uses AGP's experimental self-instrumenting mode (`android.experimental.self-instrumenting=true`) so Macrobenchmark runs with correctly instrumented code. Keep the target app's dedicated benchmark build minified/profileable; do not apply broad cross-APK dependency keep rules. Its R8 config narrowly ignores the JDK-only `javax.lang.model.element.Modifier` reference from Error Prone/J2ObjC annotation metadata; annotation processing APIs are not loaded at runtime. After the final WindowInsets change, a 30-iteration cold-start connect-screen run passed on the dedicated emulator (`OK (1 test)`, 73.885 seconds): initial/full-display time median 514.895 ms and P95 578.376 ms (nearest-rank, 29th sorted sample (zero-based index 28)); frame-overrun P95 378.675 ms. JSON metrics: `C:/aa-tmp/startup30-final.json`. These emulator-only observations are not a final performance baseline or acceptance. A physical-device run yielded zero valid samples: the attached arm64-only phone's logcat reported missing `dex2oat32`, while read-only inspection found `dex2oat64` present and a `zygote64_32` configuration. This points to a possible custom ART/runtime limitation, but does not prove the complete cause; no system or build-mode changes were made. Emulator benchmark output labels include `EMULATOR_` and are diagnostic only, not physical-device performance evidence. Do not run Gradle `connected*` tasks in a multi-device environment: they may select unintended transports. Install/run only against the explicitly selected disposable emulator/device and record its serial. M1 performance acceptance remains open. The scroll scenario needs fixed demo-server data; report device/API/refresh-rate/ABI, build variant, startup mode, sample count, P50/P95 and frame outliers. Do not claim performance acceptance from compilation.
