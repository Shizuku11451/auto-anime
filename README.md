# Auto-Anime · 自动追番

**一个使用 Go 编写、适合 NAS Docker 部署的 RSS 自动追番服务**

订阅番剧 RSS → 自动识别集数 → 提交 Aria2 / qBittorrent / Transmission 下载 → 归档到 NAS 媒体库

## ✨ 功能特性

**订阅与解析**
- 支持 RSS 2.0、RSS 1.0/RDF、Atom 格式，优先读取 enclosure 资源链接
- 包含 / 排除关键词双重过滤，按资源地址自动去重
- 添加订阅后立即执行首次同步；同步失败会保留订阅并显示错误原因
- 添加前可「预览匹配条目」检查地址和过滤规则（显示读取总数与匹配数，最多展示 20 条标题，不写入数据库）
- 订阅卡片对超长名称、地址和关键词省略显示，悬停可查看完整内容；手机窄屏下操作按钮自动换行。
- 支持从其他 RSS 阅读器导入 OPML（含嵌套目录）

**找番（内置资源搜索）**
- 侧栏「找番」按关键词搜索资源站，同一番剧、字幕组、清晰度和已识别字幕语言的多集合并展示；点「订阅此版本」自动预填过滤条件，预览确认后订阅
- 内置 ACG.RIP 搜索源（实测可国内直连匿名搜索）；结果展示识别出的番剧名、字幕组、集数与清晰度
- 可在设置页配置**自定义 RSS 搜索模板**（含 `{keyword}` 占位符）接入任何支持 RSS 输出的搜索地址，作为内置源的备用
- 搜索走统一出站配置（`PROXY_URL` 生效），响应限制 8 MB、超时 20 秒、最多展示 60 条；资源站搜索失败时显示具体原因

**番剧识别**
- 从资源标题自动提取字幕组、集数与清晰度
- 兼容 `[07]`、`S01E09`、`- 09`、`第08话`、`[09v2]` 等常见命名
- 「第三季」「S01」「3期」等季标记不会误判为集数
- 始终保留原始标题，识别字段为本地规则解析结果
- **封面识别**：按识别出的番剧名查询 Bangumi（bgm.tv），封面下载到本地缓存后在条目列表显示；名称不匹配的搜索结果不会被采用，查不到的番剧显示占位图，一周后自动重试；Bangumi 不可达只影响封面，不影响订阅和下载

**番剧库**
- 支持手动新建、卡片直接编辑、合并与删除；可按名称搜索、筛选无资源/有已保存资源的番剧，并按名称、最近收录或资源数量排序。进入「批量管理」后可全选当前结果、批量合并或删除。
- 合并将来源资源和定向订阅归入所选目标，保留原集数与有效季号，后续采用目标的规则、封面绑定和存储设置；已有媒体文件、NFO 与路径不迁移，需调整文件时使用条目纠错迁移。
- 删除前显示番剧清单与资源数量并要求确认，删除包含全部资源记录，同时暂停并解除定向订阅的归属；磁盘文件和外部下载器任务保留。非定向订阅或手动恢复订阅后仍可能重新收录。排队或下载中的资源需完成后再管理；每批最多 500 部，失败时整批回滚。
- 番剧、季、集与资源的统一视图：识别出的番剧自动入库，按季分组、按集聚合不同字幕组 / 清晰度的多个版本
- 数字集数 `7`、`07`、`007` 聚合为同集，资源仍保留原始编号；集数统计区分季号，特别篇编号不作推断合并
- **多来源规则**：为番剧配置包含 / 排除关键词，任何订阅源命中规则的条目自动归入该番剧；保存后可一键「应用到现有条目」回溯归并，手动纠错过的条目不受影响
- **元数据绑定**：在 Bangumi 搜索候选并手动绑定正确条目，封面与译名立即更新，番剧根目录生成含 `uniqueid` 的 `tvshow.nfo`；解绑后恢复自动识别
- **手动纠错**：条目可改判到其他番剧、修正季号 / 集数，已保存的媒体文件可一并迁移到新位置；纠错过的条目不再被规则移动
- 文件迁移先准备新媒体与 NFO/JSON，再更新记录，成功后才清理原文件；目标冲突或记录写入失败时保留原文件。若进程在迁移中崩溃，可能留下重复副本，需人工核对；不提供批量迁移
- 番剧支持改名（级联到条目与元数据）、默认季号与存储位置设置；备份（v3）包含番剧库配置

**下载与归档**
- 三种外部下载器联动：**Aria2 / qBittorrent / Transmission**，提交后持久化任务 ID 并轮询进度
- 直链 HTTP(S) 下载：先写临时目录，完整后一次性归档，中断不会被误标为已保存
- `.torrent` 链接自动以种子方式提交给 Aria2，不会把种子文件本身当成视频
- **媒体库友好归档**：一部番一个独立文件夹，识别到集数的资源按 `番剧名/Season 01/番剧名 - S01E01.mp4` 存放（附同名 `.nfo` 与 `-info.json`），飞牛影视 / Emby / Jellyfin / Plex 可直接刮削；同番不同字幕组自动合并到同一目录，重名冲突自动加序号
- **媒体库目录**：可单独指定番剧库根目录（`LIBRARY_DIR` 或设置页），媒体服务器直接扫描该目录，与下载目录分离；BT 多文件资源的主视频也会重命名为 `番剧名 - SxxEyy`，番剧根目录自动生成 `poster.jpg` 封面
- **自定义存储位置**：在条目上点「位置」可为单部番指定存储目录和季号（如第二季改 `Season 02`），留空恢复默认；配置随备份导出
- 下载完成后**复制**归档到媒体库，下载器任务保持做种不受影响
- 自动生成 `info.json` 与同名 `.nfo`，便于 Emby / Jellyfin 刮削
- NFO/JSON 写入实际采用的季号（条目覆盖优先，其次番剧默认季，最后第 1 季），与目录一致；已有文件需勾选纠错迁移后才重写元数据
- 容器重启后自动恢复排队任务与正在跟踪的下载器任务

**管理界面**
- **首次安装引导**：全新部署后自动进入初始设置页，一步步完成管理员账户、下载方式、代理与同步周期，跳过也可之后再配置
- **设置页**：侧栏「设置」可随时修改管理员账户、下载模式与下载器地址凭据、路径映射、出站代理、同步周期，保存后立即生效，无需重启
- 普通保存无需重填管理员密码；设置先完整校验并事务保存，失败不应用部分配置。修改用户名须同时填写新密码；更新密码会注销所有旧会话，页面跳回登录页
- **账户登录**：设置 `WEB_USER` 和 `WEB_PASSWORD`（或通过引导 / 设置页配置）后启用独立登录页，支持亮 / 暗主题；登录会话 30 天有效，右上角可一键退出
- 亮色 / 暗色主题一键切换：未手动选择时跟随系统偏好，选择保存在浏览器本地
- 基于 Vue 3 的管理面板：左侧导航切换「番剧库 / 最近条目 / 订阅管理 / 找番 / 设置」，手机端为顶栏 + 底部标签栏；页面切换、列表入场、弹窗、主题切换均带过渡动画，系统开启「减少动态效果」时自动降级
- 界面图标统一使用 Lucide 图标集（随构建产物本地打包），全程不使用表情符号
- 状态筛选徽章（计数来自全库）、关键词搜索、下载实时进度条、失败原因展示
- 添加 / 编辑 / 删除 / RSS 预览均使用弹窗与右下角通知交互
- 样式、脚本与图标随应用本地提供，**零公共 CDN 依赖**

**运维能力**
- Docker healthcheck 健康检查；公开 `/api/health` 供探针使用
- 可选账户登录保护：登录失败连续 5 次临时锁定来源 IP 15 分钟；脚本调用仍可使用 Basic Auth
- **出站代理**：RSS 不可达或 Bangumi 访问慢时，配置 `PROXY_URL` 让公网请求走代理，支持 HTTP / HTTPS / SOCKS5
- JSON 备份 / 恢复订阅，Webhook 事件通知

## 🚀 快速开始

### Docker Compose（推荐）

```bash
git clone https://github.com/sssshj114/auto-anime.git
cd auto-anime

# 编辑 docker-compose.yml，把数据目录映射到 NAS 实际路径
# 例如 /volume1/docker/auto-anime:/data

docker compose up -d --build
```

启动后访问 `http://NAS地址:8000`，等待容器管理器显示 `healthy` 即可开始添加订阅。

### 从源码构建

需要 Go 1.23+，无需 CGO：

```bash
CGO_ENABLED=0 go build -o auto-anime .
./auto-anime
```

SQLite 驱动为 `modernc.org/sqlite`（纯 Go 实现），可直接交叉编译 Linux amd64 / arm64。

### 前端开发

管理界面源码在 `web/`（Vue 3 + Vite + TypeScript），构建产物已提交到 `static/`，运行程序和构建 Docker 镜像都不需要 Node。只有修改界面时才需要：

```bash
cd web
npm install
npm run dev     # 开发服务器 http://127.0.0.1:5173/，/api 请求代理到本机 8000 端口的 Go 服务
npm run build   # 类型检查 + 打包，输出到 ../static/，把产物一起提交即可
```

## ⚙️ 环境变量

### 基础配置

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `DOWNLOAD_MODE` | `direct` | 下载方式：`direct` 直链 / `aria2` / `qbittorrent` / `transmission` |
| `DOWNLOAD_DIR` | `/data/downloads` | 归档根目录 |
| `LIBRARY_DIR` | 空（用 `DOWNLOAD_DIR`） | 媒体库目录：番剧文件夹的根目录，供飞牛影视 / Emby / Jellyfin 扫描；也可在设置页修改 |
| `DB_PATH` | `/data/auto-anime.db` | SQLite 数据库路径 |
| `POLL_MINUTES` | `30` | RSS 定时同步周期（分钟，最小 5） |
| `DOWNLOADER_POLL_SECONDS` | `30` | 下载器任务进度轮询间隔（秒，最小 5） |
| `PORT` | `8000` | Web 服务监听端口 |
| `COVERS_DIR` | `/data/covers` | 封面本地缓存目录 |
| `PROXY_URL` | 空（直连） | 出站代理地址，支持 `http://` `https://` `socks5://` `socks5h://`，见下方说明 |

### 出站代理（PROXY_URL）

默认**显式直连**，不读取系统代理设置；只有配置了 `PROXY_URL` 才走代理。地址写法：

```
http://192.168.1.10:7890
socks5://192.168.1.10:1080
http://用户名:密码@192.168.1.10:7890     # 需要认证的代理
```

- **走代理的流量**：RSS 同步与预览、直链 HTTP(S) 下载、`.torrent` 文件下载、Bangumi 封面识别、Webhook 通知
- **始终直连**：Aria2 / qBittorrent / Transmission 的 RPC 调用——它们通常在 NAS 本机或局域网，远程代理无法访问，走代理反而会失败
- 代理只影响本程序发起的请求；BT 任务在下载器内部下载，流量路径由下载器自身决定
- 代理地址会在日志和管理界面「运行状态」卡片中显示，但**账号密码会被隐藏**
- 设置页保存未变的代理地址会保留认证信息；需清除时勾选「清除代理账号密码」。更换代理地址不沿用旧地址的凭据；清空地址恢复直连
- 配置了无法解析或不支持的协议时服务拒绝启动并给出原因，避免静默绕过代理造成"看起来能用其实没走代理"

### 封面识别（Bangumi）

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `BANGUMI_ENABLED` | `true` | 设为 `false` 关闭封面识别，条目只显示占位图 |
| `BANGUMI_API` | `https://api.bgm.tv` | Bangumi API 地址，一般无需修改 |

封面请求显式直连（不读取系统代理），每次查询间隔 0.5 秒；封面只在首次识别时下载一次并缓存到 `COVERS_DIR`，浏览器加载的是本地缓存副本。封面缓存不包含在备份中，删除缓存目录后会按需重新下载。

### Aria2

| 变量 | 说明 |
| --- | --- |
| `ARIA2_URL` | RPC 地址，如 `http://NAS地址:6800/jsonrpc` |
| `ARIA2_TOKEN` | RPC secret（可选） |
| `ARIA2_DIR` | Aria2 容器内的下载目录 |
| `ARIA2_LOCAL_DIR` | 同一目录映射到本容器的路径；两侧路径相同时可省略 |

HTTP(S) 直链走 `addUri`；`.torrent` 链接由本程序读取后经 `addTorrent` 提交。

### qBittorrent（需要 4.4+）

| 变量 | 说明 |
| --- | --- |
| `QBIT_URL` | WebUI 地址 |
| `QBIT_USER` / `QBIT_PASSWORD` | 登录账号，密码只从环境变量读取 |
| `QBIT_SAVE_PATH` | qBittorrent 容器内的保存目录 |
| `QBIT_LOCAL_DIR` | 同一目录映射到本容器的路径 |

磁力链接直接提取 infohash 跟踪；种子链接通过 `auto-anime-<条目ID>` 标签发现任务。

### Transmission

| 变量 | 说明 |
| --- | --- |
| `TRANSMISSION_URL` | RPC 地址 |
| `TRANSMISSION_USER` / `TRANSMISSION_PASSWORD` | 登录账号，自动处理 RPC session ID |
| `TRANSMISSION_DOWNLOAD_DIR` | Transmission 容器内的下载目录 |
| `TRANSMISSION_LOCAL_DIR` | 同一目录映射到本容器的路径 |

### Web 与通知

| 变量 | 说明 |
| --- | --- |
| `WEB_USER` / `WEB_PASSWORD` | **同时设置两者**才启用登录；只设置其一不启用。也可通过首次安装引导或设置页配置（数据库优先） |
| `WEBHOOK_URL` | 事件通知地址（可选） |

启用后浏览器访问任何页面都会先跳转到登录页，登录成功写入会话 Cookie（HttpOnly，30 天），侧栏「退出登录」可随时注销；`curl` 等脚本可继续使用 `-u 用户:密码` 的 Basic Auth 方式调用 API。登录会话保存在数据库中，服务重启后仍然有效。

### 用户设置（数据库）

除环境变量外，以下设置保存在数据库（`/data` 内）并可随时在**设置页**修改，数据库值优先、立即生效：

- 管理员用户名与密码（密码只存盐值哈希，页面上只能重设、不能查看）
- 下载模式与 Aria2 / qBittorrent / Transmission 的地址、凭据、路径映射
- 出站代理 `PROXY_URL`、RSS 同步周期 `POLL_MINUTES`
- 媒体库目录 `LIBRARY_DIR`：番剧库根目录，番剧文件夹默认归档在这里（单部番的「存储位置」设置优先级更高）
- 找番自定义搜索源：RSS 地址模板，须包含 `{keyword}` 占位符（如 `https://example.com/search?term={keyword}`），留空只用内置源

首次部署且未配置任何凭据时，访问面板会自动进入**初始设置引导**（可跳过）；这些设置随 `/data` 中的数据库持久化，重启不丢失。环境变量适合容器编排，页面设置适合运行中调整——两者都未提供时使用默认值。

## 📥 下载器路径映射（重要）

> 这是外部下载器联动**必须理解**的配置。

下载器把文件存放在**下载器容器自己的目录**里，自动追番容器必须能读到同一位置才能归档：

- `QBIT_SAVE_PATH`、`ARIA2_DIR`、`TRANSMISSION_DOWNLOAD_DIR` 描述**下载器一侧**的路径
- `QBIT_LOCAL_DIR`、`ARIA2_LOCAL_DIR`、`TRANSMISSION_LOCAL_DIR` 描述同一目录映射到**本容器内**的路径

两个容器必须把**同一 NAS 目录**分别挂载到这两个路径上。只配置下载器一侧会导致归档一直失败，并会在条目上显示具体原因。

## 📖 使用说明

**找番**

在「设置 → 媒体库」可开启「自动清理空番剧」，**默认关闭**。开启并保存后立即检查一次，之后服务启动时及每分钟检查；关闭后停止后续清理。仅删除没有资源、没有订阅通过「归入番剧」关联（包含暂停订阅）、没有手动元数据绑定或自定义搜索名、季号、存储位置、包含/排除规则的空记录。旧条目按标题关联及旧存储配置也会受到保护。清理同时移除相应自动元数据记录，不删除 NAS 媒体、目录或封面文件。设置保存在数据库，重启保留，无新增环境变量；现有 JSON 备份不包含 settings 表。

侧栏「找番」的流程：输入番剧名 → 选择搜索源 → 搜索 → 选择字幕组和版本 → 核对匹配条目 → 保存。相同版本的多集折叠成一个选项，展开可看集数、原始标题和发布时间，不必逐集添加。

- 顶部显示版本数、资源数和可复制的 **RSS 地址**；不再提供把所有搜索结果直接订阅的按钮。
- 「订阅此版本」预填番名、带原始括号的字幕组、清晰度与已识别的字幕语言关键词，保存前自动预览实际匹配的资源。规则变更需重新预览，预览失败或零匹配不能保存。识别是启发式的，请核对原始标题；未知字幕组默认关闭自动下载。
- 「归入番剧」预填清理标签与斜线分隔别名后的名称，可选择库中已有番剧或手动修改。后续匹配条目统一归入这个名称，优先于番剧的多来源规则，避免发布标题变化拆出多张卡片；留空保留原来的自动识别行为。普通订阅编辑也支持此字段。
- 相同 RSS 地址仍只能有一条订阅；已存在时按钮变为「改为此版本」，打开原订阅并预填新的规则，保存后影响后续同步。改规则、改归属均不会合并、删除或迁移已有条目和媒体文件；已有宽泛订阅需要在此调整，其他重叠订阅仍会独立同步。
- 去重仍按资源 URL；同集的修正版或其他不同链接可能作为多份资源保留，尚未实现按集数择优替换。已有重复番剧可逐条纠错，或使用番剧详情的多来源规则回溯归并，不会自动按相同封面合并。
- `target_title` 存在订阅记录上，随 JSON 备份恢复；旧备份缺省为空，沿用自动识别。无新增环境变量或容器配置。
- 「资源页」在新标签页打开资源详情页；磁力 / 种子条目订阅后仍按「下载方式」设置处理（直链模式下进入「等待下载器」）
- 内置源目前只有 **ACG.RIP**（2026-09-07 实测可国内直连匿名搜索）。蜜柑计划的搜索接口与动漫花园的关键词 RSS 当时对匿名请求不可用（返回空结果 / 不按关键词过滤），故未内置；资源站不可达时可在设置页配置自定义 RSS 搜索模板更换来源
- 搜索只查询资源站，不会自动下载任何内容；订阅后的行为与普通订阅完全一致

**条目状态**

| 状态 | 含义 |
| --- | --- |
| 待下载 | 已通过过滤，等待下载 |
| 下载中 | 直链下载进行中（显示进度条） |
| 已发送到下载器 | 已提交外部下载器并持续跟踪进度 |
| 已保存 | 文件已完整归档到 NAS 目录 |
| 下载失败 | 任务出错或被删除，显示具体原因 |
| 等待下载器 | 直链模式下的磁力 / 种子链接，需切换下载模式 |

> 提交到下载器只代表任务已受理；文件复制进归档目录后才标记「已保存」。归档失败时保留进度与原因，问题解决后下一轮自动重试，无需重新下载。

**备份与恢复**
- `GET /api/backup` 下载 JSON 备份，**不包含**下载器密码和 Webhook 地址；v3 备份包含番剧库（规则、季号、存储位置、Bangumi 绑定），v2 备份中的存储位置恢复时自动并入番剧库
- 「恢复订阅」按 RSS 地址去重合并，不覆盖历史条目、不删除下载文件

**媒体库结构（飞牛影视 / Emby / Jellyfin）**

识别到集数的资源按下列结构归档：

```
{媒体库目录}/
└── 夏日动画/
    ├── tvshow.nfo                  # 番剧名与 Bangumi 绑定（绑定后含 uniqueid）
    ├── poster.jpg                  # 番剧封面（识别到 Bangumi 封面后自动镜像，扩展名随封面格式）
    └── Season 01/
        ├── 夏日动画 - S01E07.mp4
        ├── 夏日动画 - S01E07.nfo
        └── 夏日动画 - S01E07-info.json
```

- 媒体库目录默认就是 `DOWNLOAD_DIR`；在设置页「媒体库目录」或环境变量 `LIBRARY_DIR` 指定独立的番剧文件夹后，媒体服务器直接扫描该目录即可，单部番的「存储位置」优先级更高
- 识别不到集数的资源（剧场版、NCOP 等）放在番剧文件夹根目录，保留原始文件名
- BT 多文件资源以 `番剧名 - SxxEyy` 集文件夹存放，内部保留下载器原始目录结构；其中**最大的视频文件会重命名为 `番剧名 - SxxEyy`**（飞牛影视等刮削器按文件名识别集数，不依据文件夹名），字幕等附属文件保留原名
- 同一部番的第二季：在条目上点「位置」或番剧「编辑规则与位置」把季号改为 2，文件名会变成 `S02Exx`；纠错迁移时主视频与集文件夹会同步改名

**飞牛影视（fnOS）接入步骤**

1. 设置页配置「媒体库目录」（如 `/vol1/1000/番剧`，注意容器内需以读写挂载）
2. 飞牛「影视」应用创建媒体库时选择该文件夹，类型选「剧集」或「动漫」
3. 建议在媒体库高级设置开启「**优先读取本地 NFO 和图片**」：番剧名、季集编号、封面直接来自本程序生成的 `tvshow.nfo`、每集同名 `.nfo` 与 `poster.jpg`，不依赖 TMDB（国内直连 TMDB 常不可达），网络元数据只补缺失部分
4. 识别不到集数的资源保留原始文件名，飞牛可能显示为「未知集」；可在条目上纠错集数并勾选迁移，文件会按标准命名重新归档
- 更改只影响之后归档的集数；已归档的文件通过条目「纠错 → 同时迁移已保存的媒体文件」移动到新位置，或保持原位

**番剧库**

- 侧栏「番剧库」按番剧聚合全部资源：卡片显示封面、资源与集数统计，点开查看季 / 集分组详情，同一集的不同字幕组版本聚合展示
- 识别拆分（如同一部番因标题带清晰度标签分成两个条目）时，在番剧「编辑规则与位置」填写包含关键词并点「应用到现有条目」，即可把分散的条目归并到一起
- 标题识别错误时，在条目上点「纠错」改判番剧 / 季 / 集；勾选迁移会把已保存文件一并挪到正确位置
- 封面或译名不对时，在番剧详情点「元数据绑定」搜索 Bangumi 重新绑定；「解除绑定」回到自动识别

**删除行为**
- 删除订阅或条目只删除记录，**不会**删除 NAS 上已保存的媒体文件

**做种与空间**
- 归档是**复制**而非移动，下载器中的任务和文件保持原样继续做种；磁盘占用会翻倍，请规划好容量
- 下载器中的任务不会被自动删除，是否停止做种由你决定

**安全**
- RSS 地址、下载器密码、Webhook 凭据不会出现在日志、状态接口和备份中
- 登录会话在数据库中只存随机令牌的 SHA-256 哈希；登录接口按来源 IP 限速，连续失败 15 分钟内拒绝再试
- 若 NAS 端口对局域网外可见，建议设置 `WEB_USER` 和 `WEB_PASSWORD`；`/api/health` 始终公开供 Docker healthcheck 使用

**Webhook 事件**

配置 `WEBHOOK_URL` 后，以下事件会以 JSON POST 推送：

`new_item` · `download_submitted` · `download_saved` · `download_failed`
