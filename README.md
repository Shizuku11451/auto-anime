Auto-Anime 把追番过程中重复的工作交给服务完成：从 RSS 或搜索结果订阅资源，按规则过滤并交给下载器，下载完成后整理成媒体服务器可以直接识别的目录、NFO 和封面。

## 适合什么场景

- 想在 NAS 上长期订阅番剧，不想手动盯 RSS 和搬运文件。
- 使用飞牛影视、Emby、Jellyfin 等媒体服务器管理本地收藏。
- 需要一个中文、手机可用，并且能在浏览器里查看下载状态的管理界面。

## 功能一览

| 订阅与发现 | 下载与归档 | 管理体验 |
| --- | --- | --- |
| ACG.RIP、蜜柑计划、动漫花园搜索 | 内置 qBittorrent（Docker） | 首次设置向导 |
| RSS / Atom、OPML 导入 | 直链、Aria2、qBittorrent、Transmission | 手机适配与亮暗主题 |
| 包含 / 排除关键词与定时同步 | 自动识别番剧、季、集并整理文件 | 内置播放器与断点续播 |
| 资源去重、可用性检测 | NFO、封面和标准 Season 目录 | 备份、Webhook 与版本更新 |

界面支持亮暗主题与手机布局。番剧库默认使用横向信息卡片，可切换海报墙；星期导航在手机上横向滑动，日期与资源范围收进「筛选与日期」，缺少封面时显示番名占位。点击卡片进入详情后可编辑、合并或删除；订阅管理支持按名称、番剧、关键词搜索及状态筛选。设置按下载、媒体库、网络、账户、更新分类，修改后统一保存，离开时提示未保存的更改。桌面侧栏「服务与备份」及手机顶部菜单提供运行状态、备份、恢复与 OPML 导入入口。

## Docker 部署

**飞牛 fnOS 用户：**打开[飞牛图形界面安装指南](docs/FNOS.md)，把[飞牛 Compose 配置](deploy/fnos/docker-compose.yml)完整粘贴到「Docker → Compose → 创建项目」，即可安装；无需下载源码或自行安装 qBittorrent。默认配置把项目目录下的 `data` 与 `media` 映射为 `/data`、`/media`，不需要另外填写 NAS 路径。

想自定义番剧目录时，把配置里 `./media:/media` 左侧改成已建好的 NAS 文件夹（如 `/vol1/1000/ani`）即可；也可以下载[离线安装配置页](deploy/fnos/install.html)用浏览器打开，填写实际路径后复制生成的完整 Compose，不联网也能用（GitHub 文件页选「下载原始文件」，直接查看源码不会运行页面）。容器启动后同一页面也可从局域网访问 `http://NAS地址:8000/install`，用于后续更换媒体目录或端口。首次向导默认沿用 `/media`，可检测部署目录的挂载与写入权限。

也可以安装飞牛应用包：`auto-anime-<版本>-fnos.fpk` 提供安装向导与桌面图标，默认媒体库是共享目录 `auto-anime/media`（已只读授权给飞牛影视）。自定义目录时，在「应用设置 → 访问权限」授权具体文件夹，重启应用同步挂载，再在网页「设置 → 媒体库目录」填同一路径并检测。包只挂载授权媒体目录，容器内不能访问宿主应用包与配置。构建方法和验证边界见[飞牛应用包](docs/FNOS_APP.md)。

其他 Docker 环境可使用仓库根目录的 Compose，默认直接拉取发布镜像。数据仍保存在 `docker-data/`，包含数据库、下载器状态、源文件和封面，已有部署无需改目录。

```bash
git clone https://github.com/Shizuku11451/auto-anime.git
cd auto-anime
docker compose pull
docker compose up -d
```

打开 `http://NAS地址:8000`，按向导设置账户、下载方式、保存目录并确认。Docker 模式默认使用内置 qBittorrent，不需要填写下载器地址或密码。媒体库目录会沿用部署配置；首次安装可保留默认值，代理无需填写。

部署到 NAS 时，把 `docker-compose.yml` 里的数据卷改成 NAS 上的持久化目录，例如：

```yaml
volumes:
  - /volume1/docker/auto-anime:/data
  # 归档/媒体库目录：也要在这里映射进容器，且容器内路径与设置页填写的一致
  # 飞牛 fnOS（存储空间1 的用户目录）示例：- /vol1/1000/番剧:/vol1/1000/番剧
```

| 端口 | 用途 |
| --- | --- |
| `8000/tcp` | Web 管理页面 |
| `6881/tcp`、`6881/udp` | BT / DHT |

网页端口冲突时只改映射左侧，例如 `18000:8000`，随后访问 18000；BT 端口冲突时同时修改 TCP、UDP 映射两侧和 `QBITTORRENT_BT_PORT`。无需映射内置下载器的 8080 端口。

发布镜像下载需要 NAS 能访问 GHCR；Git 克隆需要访问 GitHub。镜像无法拉取时先处理镜像获取问题，网页里的代理设置不能帮助 Docker 拉取镜像。应用启动后默认直连，管理页面不依赖境外 CDN；RSS 和元数据可用性取决于所选来源。

源码构建请在完整仓库根目录执行 `docker compose -f docker-compose.yml -f docker-compose.build.yml up -d --build`。构建还需要下载基础镜像、Go 依赖与 Alpine 软件包；自改前端须先在 `web/` 执行 `npm ci` 和 `npm run build`。发布镜像与本地构建的更新差异见[配置参考](docs/CONFIGURATION.md)。

## 三步开始追番

1. 在「找番」搜索番名，或在「订阅管理」添加 RSS；设置字幕组、关键词和保存位置（归档目录需已映射进容器，见[文件归档](#文件归档)）。
2. 开启自动下载，在「最近条目」查看队列、进度和失败原因。
3. 在「番剧库」查看已归档的季集；需要时重新识别、绑定 Bangumi 或迁移文件。更新日默认自动读取 Bangumi 明确标注的放送星期，已有资料会后台补全；详情中点「编辑番剧」可按字幕组出片时间手动覆盖，改回「自动获取」后跟随资料。支持周一至周日、「查看今天」或日期选择，未知日期归入「待补充」。官方放送日不保证资源当天更新；日期仅对应每周安排，不代表当天实际到片或仍在连载。

默认每 30 分钟同步一次 RSS，同时下载 2 个任务。两项都可以在网页「设置」或「最近条目 → 下载控制」中调整。

「找番」可直接点选搜索源，输入关键词后换源会立即搜索；搜索中可取消或提交新关键词。结果按版本合并，可按字幕组、清晰度、字幕语言筛选，并按最近发布或已发现集数排序；这些筛选只影响展示。点击「预览并订阅」核对匹配条目后保存。最近 6 次搜索仅在当前页面会话中保留，刷新即清空，也可手动清除；取消搜索保留上次结果。已发现集数不代表全季已发布。

「最近条目」按服务器端搜索和状态筛选分页，每页最多 100 条，列表顶部、底部都能翻页，较早页面可一键回到首页。搜索支持回车立即提交、清除组合筛选；状态数量是全库统计，列表单独显示当前页条数。页面每 5 秒自动更新，也可手动刷新。

条目直接展示下载进度、速度与失败原因，点击「详情」查看完整原始标题、发布时间、下载方式和归档位置，并进行纠错、调整存储位置或移除记录。批量管理工具栏滚动时保持可见，全选仅选当前页；修改搜索、切换状态或翻页会清空选区，部分失败的条目保留选中供重试。移除记录不删除已保存文件。「下载控制 → 调整并发」展开设置，默认同时下载 2 个任务，范围仍为 1–32；此次界面调整不改变下载目录、下载器归属或已有任务。

## 文件归档

默认媒体库位于容器内的 `/data/downloads`。识别到集数的资源会整理为：

```text
番剧名/
├── tvshow.nfo
├── poster.jpg
└── Season 01/
    ├── 番剧名 - S01E01.mp4
    └── 番剧名 - S01E01.nfo
```

资源标题会先做一次标题分析：字幕组、片源、编码、分辨率、字幕语言（`[WebRip][1080p HEVC AAC][简繁内封]`）与校验码（`[ABCD1234]`）这类标签既不进番剧名也不进目录名——无论写在方括号、圆括号（`(BD 1920x1080 x265)`）还是裸写在标题里（`摇曳百合 第01话 GB 1080P MP4`）。季与集分开解析（`3期`、`S3`、`第三季`、`3rd Season`、`II` → 季号，`S03E01` → 第 3 季第 1 集），`[01-12合集]`、`01~24` 这类合集区间不会被当成某一集。标题是「中文名 / 原名」这种双语形式时，番剧名取中文那段，不同字幕组的同一部番更容易归并到一起。

标题里写在前面的方括号如果其实是番剧名（`[咒术回战][01][1080p]`、`[无职转生] 第01话`）会当名字用；`無職転生Ⅲ` 这类罗马数字、以及挡在集数前面的年份（`无职转生 2023 - 01`）分别按季号与噪声处理。中文技术词只在与作品名之间有分隔（空格、括号）时才清理，「我们的重制人生」这类名字不会被啃掉一块；代价是 `无职转生简体内嵌第01话` 这种完全连写的标签不再清理。

**番剧名与番剧文件夹用同一个规范名**：匹配到 Bangumi 资料后自动改成官方名（优先中文名，其次日文原名，并剥掉「第三季」这类季标记，季由 `Season XX` 目录承载）。改名会同步条目、订阅目标名、NFO 与元数据；**已有媒体文件的目录不会被搬动**，只有空目录或只含 `poster.jpg`/`tvshow.nfo` 的目录才会跟着改名。季号优先级：条目上手动指定的季 > 番剧设置里的季 > 标题解析出的季 > 第 1 季。

不带序号的季标记（`进击的巨人 最终季`、`… 完`）没法确定季号，会保留在番剧名里。标题解析出的季在识别资源时写进条目，**升级前已收录的条目没有这份信息**，归档时按番剧设置或第 1 季处理。

默认 BT 下载器会保留源文件用于做种，再复制一份到媒体库，请预留足够空间。首次向导或设置页可关闭「保留下载器原文件做种」；关闭后只在归档成功后删除本次源文件，不会批量删除已有条目源文件。媒体服务器扫描媒体库根目录即可读取本地 NFO 和封面。

### 归档目录必须映射进容器

上面的根目录（设置页「媒体库目录」、单部番剧存储位置、订阅保存位置）都是**容器内路径**。Docker 不会阻止程序写入未映射的绝对路径，但文件会落在容器自己的文件系统里：任务照样显示「已保存」，NAS 文件管理里却看不到，容器重建后还会丢失。

想归档到 NAS 的 `/vol1/1000/番剧`（飞牛 fnOS 存储空间 1 的用户目录），先在 `docker-compose.yml` 的 volumes 里映射：

```yaml
volumes:
  - /volume1/docker/auto-anime:/data
  - /vol1/1000/番剧:/vol1/1000/番剧
```

容器内路径与设置页/订阅里填写的路径必须一致；也可以映射成别的名字，此时要填容器内的那个路径。映射后重启容器。保存「媒体库目录」「保存位置」或番剧存储位置时程序会检测目录是否已映射，未映射会明确提示。已有条目的文件不会自动搬迁，需要迁移时用条目「纠错」勾选迁移。

## 下载模式

Docker 默认使用 `builtin`，适合直接开箱使用。也可以在设置页或环境变量中切换：

| 模式 | 适用情况 |
| --- | --- |
| `builtin` | 使用容器或 Windows 桌面包内置 qBittorrent，支持磁力和种子 |
| `direct` | 只由 Auto-Anime 下载 HTTP(S) 文件 |
| `qbittorrent` | 连接外部 qBittorrent |
| `aria2` | 连接外部 Aria2 |
| `transmission` | 连接外部 Transmission |

Windows 用户可下载 Release 中的 `-windows-amd64-desktop.zip`，完整解压后双击 `Auto-Anime.exe`：独立桌面窗口沿用现有界面，随包 qBittorrent 默认处理磁力和种子，关闭窗口后在系统托盘继续运行，右键托盘可退出并停止下载器。需要 Windows 10/11 x64 和 Microsoft Edge WebView2 Runtime。默认数据位于程序同级 `data\`，支持盘符路径和 UNC 网络共享；详细步骤、构建及兼容性见 [Windows 使用说明](docs/WINDOWS.md)。单独 `.exe` 不含下载器，缺少随包文件及 `QBITTORRENT_PATH` 时仍告警并临时降级为 `direct`。完整环境变量、外部下载目录映射、代理、备份和更新源说明见[配置参考](docs/CONFIGURATION.md)。

内置 qBittorrent 运行中意外退出时，主服务保持运行，并自动退避重启下载器，重试间隔从 2 秒逐步增加到最多 60 秒。恢复沿用原配置和任务；WebUI 就绪后的前 90 秒内，暂未出现的旧任务不会立即判定失败，暂停状态与进度保留。该等待期结束后仍不存在的任务会按原规则报错，不自动重新提交。需要持久化整个 `QBITTORRENT_DATA_DIR` 才能保留会话和源文件。

## 本地开发

后端需要 Go 1.23+。前端使用 Vue 3、Vite 和 TypeScript，建议 Node.js 22.12+。

```bash
# 终端 1：启动后端，默认使用 direct 下载模式
cd backend
go run .
```

```bash
# 终端 2：启动前端开发服务器
cd web
npm ci
npm run dev
```

访问 <http://127.0.0.1:5173/>。前端开发服务器会把 API 转发到本机 `8000` 端口。构建前端资源：

```bash
cd web
npm run build
```

构建产物输出到 `backend/static/`。后端数据默认写入 `backend/data/`，与 Docker 的 `docker-data/` 相互独立。

## 数据与维护

- 完整备份：停止容器后备份挂载到 `/data` 的整个目录。
- 网页 JSON 备份：用于恢复订阅、规则、存储设置和元数据绑定，不包含历史条目、下载任务和媒体文件。
- 归档文件发布前会在数据库保存提交记录；文件完成但最终状态写入失败时，后台轮询或重启会重试提交，避免重复复制，单文件和多文件合集目录均支持恢复。媒体已存在而归档标记不完整时会保留文件并提示检查，不自动删除。
- 网页登录与 Basic Auth 共用失败限流。旧版密码哈希在成功登录后自动升级；升级后的数据库应使用当前版本程序，旧版本不支持新密码格式。
- 健康检查：`GET /api/health`。
- 查看状态：`docker compose ps`；查看日志：`docker compose logs --tail=100 -f`。

更细的迁移、旧版升级和一键更新说明，请查看[配置参考](docs/CONFIGURATION.md)。
