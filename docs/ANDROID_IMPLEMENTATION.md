# Android client implementation status

M2 (technology-stack migration) is implemented: the M0/M1 prototype screens were rewritten on Compose with the same features. M3 (remote-mode parity) is implemented: download management, the library schedule filter, Bangumi search with aggregate subscription, subscription management, library correction and server settings, with list-detail panes on wide windows. The last four were functionally verified on an emulator against the real Go server with a mock upstream (see the verification notes). M1 physical-device compatibility and performance acceptance remain incomplete, and later phases in ANDROID_PLAN.md (M4 onward) are not implemented.

## Implementation

- API 26+, compile SDK 37, target SDK 36. Gradle 9.8.2 wrapper with pinned distribution checksum, AGP 9.5 with built-in Kotlin, KSP; versions in `android/gradle/libs.versions.toml`, shared module setup in `android/build-logic` convention plugins.
- Modules: `core/model` (pure Kotlin DTOs and error categories), `core/network` (server URL rules, origin cookie jar, Keystore cookie storage, OkHttp API client), `core/data` (`SessionRepository`, `SessionCalls` helper, DataStore, Hilt bindings), `core/designsystem` (theme, icons, shared components), `feature/connect|library|discover|feeds|downloads|player|settings`, `app`, `benchmark`.
- Navigation has five tabs (library, discover, subscriptions, downloads, settings). Library, discover and subscriptions use the list-detail scene: on wide windows the anime detail, its edit and binding pages, a subject's resources and the subscription editor open beside their list.
- UI: Jetpack Compose with Material 3, Hilt, Navigation 3 and Material 3 Adaptive. Phones use a bottom navigation bar; wider windows use a navigation rail and show the library and detail side by side. The player is full screen and uses the Media3 Compose player and controls. Chinese is the default UI language, with English resources. Brand colors mirror `web/src/styles/tokens.css`; dynamic color is an opt-in setting on Android 12+.
- A fresh start opens a mode choice: connect to a NAS (remote mode) or run on this device (standalone mode, M5, shown disabled as coming soon). After logout or session expiry the prefilled connect form opens directly.
- HTTPS by default; HTTP requires explicit user confirmation. Requests preserve a reverse-proxy prefix, reject cross-origin redirects, and scope encrypted Keystore AES-GCM session cookies by origin and account. Passwords are not persisted or placed in saved UI state. The saved-connection DataStore file and keys are unchanged from the prototype.
- `SessionRepository` owns connect, restore, logout and 401 expiry. Each transition advances a generation; superseded connect results, saved-connection writes and library pages are discarded, and repeated 401 reports end a session once. Each session owns its OkHttp clients and an in-memory-only Coil cover loader, all closed when the session ends; a new session starts from a fresh back stack.
- Setup/login/logout, bounded library pagination (loads further pages near the end of the grid, pull to refresh), detail, covers and saved-item Media3 streaming are implemented. A server missing the bounded page response fails with an actionable server-update message; no full-array fallback is used.
- The library shows schedule filters (all, Monday to Sunday with today marked, no known day, finished) with library-wide counts, using the paged `/api/animes` `day`, `today` and `counts` parameters added for this; the device's local date decides "finished", as in the web client. A server that returns no `day_counts` predates the filter, which is then hidden rather than shown with unfiltered results. A late page for another day is discarded. Bangumi collection entries that the web merges into its library view are not shown.
- Discover (`feature/discover`): Bangumi subject search (`/api/discover/subjects`; a newer search drops the older result) and a subject's aggregate resources (`/api/discover/resources`) grouped into versions by the web client's rules (title, group, quality, language, season; `core/model/Feeds.kt`). Subscribing to a version creates `aggregate://subject/<id>?...` with episode offset 0 and a strict season rule (the version's season, or unmarked only), then syncs once; an existing subscription for the same rules is detected by comparing decoded parameters and shown as subscribed. Subject covers from Bangumi's CDN are not loaded: the session's image loader only reaches the selected server.
- Subscriptions (`feature/feeds`): list with enable/disable, sync now and delete (confirmation; records only, saved media kept), plus an editor for new manual RSS subscriptions and existing ones (name, anime, include/exclude keywords, season rule, automatic download) with a match preview that is discarded when an input affecting matching changes. Edits keep the server's four always-sent fields and leave unsent ones unchanged; the address is fixed after creation and the storage location is not editable here. Addresses are shown as scheme and host only, since an RSS URL may carry a private token. A new subscription syncs once; a failed first sync does not fail the save.
- Library correction (`feature/library`): the detail lists every release with its status (saved ones play) and has edit (name, search name, default season, update day, include/exclude rules, optionally applied to existing items), Bangumi metadata binding and unbinding (`/api/meta/search`, `/api/animes/{id}/metadata`) and rematch. Each release can be corrected (`PATCH /api/items/{id}`): keep or name another anime (matched or created by the server), season (0 follows the anime) and episode; moving saved media is a separate, off-by-default switch. The storage location is sent back unchanged.
- Server settings (`feature/settings`): sync interval, concurrent downloads, keep source files, clean up empty anime (confirmation; records only) and the media library folder, sending only changed fields of the partial `PUT /api/settings`. Download method and proxy (already redacted by the server) are read-only; downloader connections, credentials and the account stay in the web client.
- Downloads tab (`feature/downloads`) uses the existing server API without backend changes: `GET /api/items?page=1` with `group`, `q` and `before` cursor paging, status counts from `/api/status`, `POST /api/items/{id}/download|pause|resume` and `DELETE /api/items/{id}` (record only; saved files are kept, with a confirmation). Status filters, transitions and hints mirror `web/src/utils/status.ts`; the server stays the authority and its plain-text rejection reason is shown. Search is debounced by 300 ms. While the tab is visible and the server reports downloading or queued tasks, it re-fetches the loaded range (up to three pages, merged by id) about every 2 seconds without overlapping requests, backing off exponentially with jitter to 60 seconds on failure; it stops when nothing is active or the screen stops. Results are discarded if the session, filter or search changed or a newer request started; a 401 ends the session. After an action, the row shows the state the server recorded, not an optimistic guess. Saved items open the player. The release `link` field (magnet or tracker passkey) is not decoded.
- The ExoPlayer instance exists only while the player screen is started; the position is kept in its ViewModel. The activity handles rotation and resize changes itself, so rotating does not restart playback.
- Macrobenchmark module uses AGP experimental self-instrumenting mode (`android.experimental.self-instrumenting=true`), runs the target in the test APK process, and keeps the app's benchmark build minified/profileable. Compose test tags are exposed as resource ids so the scroll scenario still finds `anime_list`; it requires fixed demo server data.
- Debug builds enable logged StrictMode thread/VM diagnostics, and a debug-only Hilt entry point (`app/src/debug`) lets instrumented tests check and reset the session they create. `ReportDrawnWhen` marks UI readiness once the startup restore finishes; it does not wait for library data or covers.
